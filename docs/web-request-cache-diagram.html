Web Request Lifecycle: Cache-Aside Architecture

Browser initiates an API call → Backend probes Redis in-memory cache → Cache Miss triggers SQL query to PostgreSQL source-of-truth → API fills Redis with TTL → 200 OK returned to Client.

1. Cache-Aside Pattern
  • Application code directly manages the cache boundary.
  • Checks Redis in-memory storage before contacting persistent disk.
  • Sub-millisecond retrieval on cache hits (0.2ms vs 15ms DB).
2. Cache Miss Fallback
  • Redis returns (nil) when key has expired or was never set.
  • API seamlessly falls back to PostgreSQL relational database.
  • Executes primary key / indexed lookup on PostgreSQL tables.
3. Lazy Population & TTL
  • API writes fresh dataset into Redis using SETEX with TTL.
  • Guarantees future requests hit memory until expiration.
  • Dispatches 200 OK response with JSON body to the browser.
